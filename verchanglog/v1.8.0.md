# v1.8.0

发布日期：2026-11-26

## 概述

TopSAP Client v1.8.0 聚焦数据面可观测性与会话失效处理。数据面健康判定补充内网 DNS 主动探活与 UDP/53 观察，降低参与判定的包数阈值，重连后的数据面验证改为三态；连接信息新增上下行收发包数。同时新增网关会话失效识别：命中 39/42/50/52/57 时停止无效的隧道级重连，断开并提示重新登录。

## 变更

### 数据面健康判定与 DNS 探活

- 新增 `session/probe.rs`：每 30 秒以虚拟 IP 为源，向网关下发的 DNS 发送标准 A 记录查询；查询名优先取门户资源中的内网域名，取不到时回退 `www.example.com`。DNS 返回正常应答或 NXDOMAIN 都视为下行可用，连续 3 次无响应且期间无下行时判定下行静默。
- 绑定虚拟 IP 失败时每 5 秒重试、最多 6 次，避免地址刚写入网卡时 Windows 返回 `WSAEADDRNOTAVAIL(10049)` 直接禁用探活；6 次仍失败才跳过主动探活，不影响隧道连接。
- UDP/53 上行纳入「期望响应」：存在 TCP、ICMP 或 UDP/53 上行且隧道下行持续为 0 时参与判定；纯 UDP 非 DNS 单向流量仍不触发。
- 单方向参与判定的包数阈值由 20 降到 6，覆盖单个连接的少量 SYN 重传。
- 重连后的数据面验证改为三态：有下行记为已恢复；有上行无下行记为未恢复并继续重试；没有上行记为「暂无流量可验证」，不再把没有流量当作已恢复。
- 非 IPv4 下行数据帧改为单独的限频日志，不再和控制帧混在一起。
- 「基本信息」新增「收发包数（上行 / 下行）」，便于现场区分「没发包」与「发了没回」。

### 会话失效识别与重连提示

- 握手确认帧与连接后的错误通告统一识别 39/42/50/52/57（会话 ID 非法、被踢出、连接超时、重连虚 IP 无效、账号受限）。
- 命中后不再复用旧 `session_id` 做隧道级重连，执行断开与网络配置恢复，阶段置为失败并提示「登录会话已过期，请重新登录」。
- 其他错误码（40/41/45/51/53/56）仍按网关拒绝处理；纯网络断线继续按用户配置的指数退避重连。
- 数据面健康检查本身未改动：15 秒窗口、30 秒宽限、DNS 探活、恢复预算与验证逻辑保持不变；仅在数据面恢复的重连过程中遇到会话失效码时提前转入重新登录提示。

## 已知限制

- DNS 主动探活尚未在真实网关完成真机回归：绑定虚拟 IP、资源路由命中、回包注入后投递到 socket 三个环节依赖平台网络栈行为，需要 Windows 10/11、macOS、Linux 分别验证。
- 会话失效识别依赖网关返回 39/42/50/52/57。若网关不返回错误码、只关闭 TCP 或握手成功但数据面不通，仍会按普通断线重连，直到次数用尽；后续可补「连续数据面失败判定会话失效」的兜底。
- 本次不做自动重新登录，由用户手动重新登录；与原 TopSAP 行为一致（原客户端最多重连 5 次后断开）。
- DNS 探活每 30 秒产生一个很小的 DNS 查询包，会体现在「收发数据」计数中，属于预期行为。
