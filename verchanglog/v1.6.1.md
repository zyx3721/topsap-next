# v1.6.1

发布日期：2026-11-16

## 概述

TopSAP Client v1.6.1 修复「网关拒绝隧道却显示连接成功」的问题。此前客户端发出登录帧后只等待任意 `type=2` 确认帧，不解析 LoginServer 握手回应；网关在回应或错误通告中返回的 `req_packet` 错误码（39~57）与 VIP/掩码为 0 被忽略。海外用户选择国内网关时会出现「隧道建立成功、收发 0 B / 0 B」的假连接，而官方客户端会在同一场景报错。

## 修复

### 握手回应校验与网关拒绝识别

- 新增 `tunnel/handshake.rs`，解析确认帧载荷的 JSON 与二进制握手回应：
  - JSON：`req_packet`、`resp_packet.vip_v4 / vip_mask / dns1_v4 / dns2_v4`；
  - 二进制：VIP 在载荷 +0x10、掩码在 +0x14（大端 32 位）。
- `req_packet` 39~57 识别为网关错误通告，映射为具体原因：会话 ID 非法、地址池失败、ACL 规则失败、被踢下线、DHCP 地址失败、客户端连接超时、DNS 列表失败、重连虚 IP 无效、服务器繁忙、集群切换、账号受限。
- VIP 或掩码为 0 判定为地址池分配失败；全零确认帧保持兼容，不误判为地址错误。
- 握手阶段的非确认帧不再丢弃；连接后收到的错误通告同样触发断开。
- 网关明确拒绝时直接显示失败原因；自动重连遇到拒绝使用 Fatal 分支停止重试，避免无效循环。
- 隧道侧 VIP/掩码与登录响应不一致时写入警告日志（暂不自动改配，保持现有 Windows/macOS/Linux 建卡时序）。
- 无法识别的回应保持 `Unknown`，回退登录响应 `net_param`，兼容旧网关。

### 错误提示与文档

- 前端 `errorText` 补充网关拒绝、地址未分配的中英文映射与测试。
- `docs/PROTOCOL.md` 新增 §3.1.1「登录回应与错误通告」；`docs/ARCHITECTURE.md` 与 `docs/CHANGELOG.md` 同步。

## 平台支持

修复位于跨平台 `tunnel` 层，Windows / macOS / Linux 共用。本次本地构建为 Windows x64；macOS / Linux 安装包由 CI 或对应平台构建。

## 已知限制

- 二进制回应的字段布局来自官方 `na_client.exe` 静态分析，尚未在问题网关上逐字段抓包；旧网关无法识别时回退 `net_param`。
- 客户端仍以登录响应 `net_param.vip_v4` 配置网卡；隧道回应 `resp_packet.vip_v4` 仅用于校验并在不一致时写警告。完全对齐官方需要把握手提前到配址之前，涉及 macOS/Unix 建卡顺序，留待后续真机验证。
- 海外选国内网关的具体错误码（50 连接超时 / 57 账号受限等）需问题用户安装后复现确认。
- 本地未生成 macOS / Linux 安装包；如需 macOS 测试包，需在 macOS 或 CI 构建。
