# v1.7.0

发布日期：2026-11-17

## 概述

TopSAP Client v1.7.0 新增启动时本机 DNS 预检与告警卡片。Windows / macOS 启动后检查默认路由网卡或网络服务的 DNS 是否为自动获取；检测到手动 DNS 时在连接页展示告警，提供「改为自动获取」与「重新检查」。首次预检结束前禁用连接与忘记密码按钮；启动自动连接在未检测到手动 DNS 时于预检结束后发起，检测到手动 DNS 时暂停，用户处理后手动连接。Linux 行为不变。

## 变更

### 启动时本机 DNS 预检（Windows / macOS）

- 启动后由后端提前执行一次预检，结果缓存到本次进程；前端与启动自动连接共享同一结果，超时上限 5 秒。
- 检测范围：默认路由所在的物理网卡（Windows）或网络服务（macOS），不扫描其他网卡。
- Windows：
  - `GetIpForwardTable` 取默认路由，`GetAdaptersAddresses` 取网卡 GUID 与连接名；
  - 读取 `Tcpip` / `Tcpip6` 接口注册表的 `NameServer` / `NameServerList` 判断手动 DNS；
  - `netsh interface ipv4/ipv6 set dnsservers ... source=dhcp` 修改并回读注册表确认；
  - 兼容 Windows 7 SP1，不依赖 PowerShell / NetTCPIP。
- macOS：
  - 默认接口映射到网络服务；
  - `networksetup -getdnsservers` 三态判断（自动 / 手动 / 未知）；
  - `networksetup setdnsservers <service> Empty` 修改并回读；
  - 沿用现有 helper 白名单与 `HELPER_VERSION`，不触发重装。
- 界面：
  - 连接页 `StatusHero` 下方展示告警卡片，包含网络名、当前 DNS 与风险说明；
  - 「改为自动获取」成功后卡片消失并提示；
  - 检测到手动 DNS 时，连接与忘记密码按钮保持禁用，直到改为自动获取成功；
  - 连接中 / 已连接禁用修改，并提示先断开；
  - 断开回到 idle 后自动刷新一次。
- 启动门禁与自动连接：
  - 首次预检结束前连接与忘记密码按钮禁用；检测到手动 DNS 时保持禁用，直到改为自动获取成功；
  - 未检测到手动 DNS：预检结束后正常启动自动连接；
  - 检测到手动 DNS：暂停自动连接，日志记录原因，卡片提示「启动自动连接已暂停；改为自动获取后请手动点击「连接」」；
  - 检测失败或超时：按未知处理并释放门禁，自动连接继续按原逻辑执行。
- 已知边界：
  - 只检查默认路由，不处理其他活动网卡的静态 DNS；
  - 手动多线路探测 `probe_lines` 发生在连接前，若静态 DNS 已导致探测失败，用户会先看到探测失败提示；本期未覆盖该路径；
  - 修改后保持自动获取，断开不恢复原静态 DNS；
  - 静态 IP + 手动 DNS 会追加警告，改为自动获取后可能没有可用 DNS；
  - 手动连接也受门禁限制，必须先处理手动 DNS 才能点击「连接」。

### 构建与 CI

- macOS amd64 构建改用 `macos-15-intel` runner，避免旧 runner 下线或兼容问题；运行时行为不变。

## 已知限制

- macOS 仍属「已实现，待真机验证」；`networksetup setdnsservers ... Empty` 的实际回读需真机确认。
- Windows 7 SP1 的 `netsh` + 注册表路径需真机回归。
- 启动自动连接遇到手动 DNS 时暂停，用户需要手动点击「连接」；这是本次确认的行为，不自动恢复连接。
- 修改本机 DNS 是持久操作，断开不恢复；卡片文案已明确提示。
- Linux 不启用本机 DNS 预检。
