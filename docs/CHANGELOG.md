# 更新记录

## 未发布

### 新增

- 断线自动重连可配置：设置新增「重连次数」（1–999 次，或勾选「无限次」），退避改为真正的指数增长 2/4/8/16/32/60 秒并加入 ±20% 抖动，无限次时封顶 60 秒；等待重连期间手动断开可立即退出（不再等满退避时间），日志显示当前次数/间隔
- 托盘连接状态图标：保留应用原图标完整外观（深色底座、盾牌轮廓与齿轮细节），只把盾牌主色按状态替换，未连接灰色、连接中（含重连）蓝色、已连接绿色、正在断开（人为）浅蓝色、异常断开红色并以约 0.7 秒亮暗交替闪烁，鼠标悬停提示同步显示「未连接 / 连接中 / 已连接 / 正在断开 / 已断开」；连接页状态卡与侧栏状态点同步采用同一套灰/蓝/绿/浅蓝/红，人为断开完成后回到灰色不提示异常；由引擎阶段变化驱动，仅在状态真正变化时更新，macOS 关闭模板渲染以保证颜色不被系统抹平
- 启动自动连接：设置新增「启动时自动连接」，启动软件后使用默认连接配置与已保存密码自动登录；仅在同时具备连接配置、账号与已保存密码时可勾选，条件不满足时开关禁用并提示缺失原因；与手动连接共用同一登录流程，失败只写运行日志
- macOS 关闭窗口后的 Dock 行为：新增设置项「关闭窗口后隐藏 Dock 图标」（默认关闭，仅在「关闭窗口时最小化到托盘」开启时可用），关闭窗口时隐藏 Dock 图标只保留菜单栏托盘；显示窗口时自动恢复 Dock。同时处理 `RunEvent::Reopen`，修复关闭到托盘后点击 Dock 图标无法唤回窗口的问题
- 隧道路由生效范围：设置窗口按网段列出登录后网关下发的全部路由（ACL 目标 + 门户资源），可逐条勾选、全部启用或全部关闭，也可手动排除网关未下发的网段（CIDR 或点分掩码）；被关闭的网段不写入系统路由表、不参与路由冲突预检与自动重连恢复，修改对下一次连接生效；每次登录缓存完整路由到 `routes_cache.json`，未连接时仍可调整
- 数据面健康检查与自愈：每 15 秒观察 TUN 收包、隧道上行/下行与网卡投递增量，识别上行卡死、持续下行静默与下行投递失败；命中后执行隧道级重连并验证双向流量，连续 3 次失败断开并提示「网关未恢复数据转发，请重新登录」；新增 90 秒冷却与 10 分钟最多 3 次恢复限制，自动重连关闭时只提示不重连
- 连接信息卡片补充「收发数据（上行 / 下行）」标签与动态工作状态，失败时展示具体原因
- 首次启动且没有任何连接配置时，提示前往「设置」-「连接管理」导入配置
- 启动版本检查：读取发布目录中的纯文本版本号，发现新版本时在侧栏版本旁显示「可更新」，弹窗提供「稍后 / 前往」并可打开下载页面；检查失败时静默跳过
- 版本检查支持点击侧栏版本号手动触发：有更新时打开弹窗，无更新提示「已是最新版本」，网络或内容异常提示「检查更新失败」；检查结果区分「无更新」与「检查失败」，避免断网时误报
- Windows / macOS 自动更新：更新弹窗新增「自动更新」，按平台/架构下载 NAS 安装包、断开 VPN、退出并由 helper 替换程序后重启；Windows 使用 PowerShell 2.0 兼容脚本替换 exe + resources，macOS 挂载 dmg 校验签名/隔离属性后替换 .app，目录不可写时请求管理员授权；更新成功后由 helper 主动清理临时下载目录，新版本启动时再兜底清理；当前不做 SHA-256 / 签名校验；Linux 保持「前往」手动下载
- macOS 路由冲突预检与接管：连接前读取 `netstat -rn -f inet`，按目标网段与掩码精确比对；发现其他接口（其他 VPN、旧会话残留或物理网络同网段）已占用时弹窗列出冲突，用户确认「接管并连接」后删除冲突路由并继续；取消或超时则中止连接。全部路由失败时也会把明细写入运行日志
- macOS 诊断页 utun 残留检测与一键清理：列出带 IPv4 地址的 utun（地址 / 对端 / MTU / 关联路由数），当前连接使用的接口标记为「使用中」且不可清理；二次确认后执行 `ifconfig utunN down` 并删除剩余关联路由；自检进行中拒绝清理
- 运行日志时间戳补充日期，格式为 `[2026-11-07 00:20:16]`；配址回退 `netsh`、路由回退 `route add` 时写入运行日志，兜底不再静默

### 变更

- `netcfg/windows.rs` 拆分为 `netcfg/windows/{mod,address}.rs`，地址配置 FFI 独立成子模块，行为不变
- `update.rs` 拆分为 `update/{mod,download,install}.rs`，版本检查、下载与平台安装分文件维护
- Windows 7 资源路由对齐官方客户端：由直接 `route add` 改为优先 IPHLPAPI `CreateIpForwardEntry`（`GetIpForwardTable` 查重与回读），失败再回退 `route add`；配址仍保持 `netsh`，不引入 PowerShell

### 修复

- 设置保存不再每次重查系统代理状态：只有代理绕过相关字段变化时才刷新，修复连续切换「无限次」等开关时的卡顿
- 启动自动连接后资源列表为空：自动连接由后端发起，前端拿不到 `connect` 命令返回的 `SessionSummary`；新增 `session_summary` 命令，前端在连接完成（或已连接状态下加载页面）时补拉会话摘要，修复自动连接后「资源列表」一直显示「暂无资源」、需手动断开重连才恢复的问题
- 关闭窗口残留：未开启「关闭窗口时最小化到托盘」时，关闭窗口改为退出程序（先执行既有断开清理），修复窗口销毁后进程仍驻留、Dock/托盘图标点不开只能强制结束的问题
- 隧道静默半开：TLS socket 开启 keepalive（空闲 30 秒、间隔 5 秒、3 次探测），隧道写线程增加 15 秒超时并响应取消，写失败/超时统一发送 `TunnelEvent::Closed` 交给自动重连；修复 NAT 失效或网关不再转发时界面仍显示已连接、上行冻结且下行长期为 0 的问题
- 自动重连：上行泵改为每个报文读取当前隧道句柄，修复重连成功后配址/路由仍在但所有流量不通的问题；每条隧道使用独立取消令牌并在替换时关闭旧连接；重连后复核并补配网卡地址、网关旁路、资源路由与 DNS，路由账本去重；增加隧道代际与重连互斥，忽略旧隧道的延迟关闭事件并处理新隧道建立后立即断开的情况；上行发送失败增加限频日志；重连后增加数据面双向验证，避免「握手成功但网关不转发」被误报为已恢复
- 重连网关 IP 优化：优先复用登录时缓存的网关 IP，直接用该 IP 建立 TLS 与旁路，避免断线后系统 DNS 仍指向 VPN DNS 导致解析长时间等待；缓存 IP 建连失败时再以 3 秒超时重新解析一次，更新旁路与缓存后重试
- 兜底日志跨平台补齐：Unix `NetConfig` 增加 `notes` / `take_notes`，修复 macOS / Linux 因缺少该方法导致的编译失败；macOS 路由 `-interface` 回退与 DNS Router 回退写入运行日志；Linux 无命令级兜底
- 兜底日志补充：三平台断开清理记录路由/DNS 回退与残留（Windows 清理后回读路由表，macOS 记录接口删除→网关回退与 DNS 恢复失败，Linux 删除后回读）；macOS 记录默认网络服务缺失时的 Wi-Fi/Ethernet 回退；Windows 记录 MTU 设置失败；清理失败时断开提示改为「已断开（部分网络配置未恢复，详见上方日志）」
- Windows 资源路由：`CreateIpForwardEntry` 的 Metric1 改为 **接口 Metric + 路由分量 1**（动态读取 `netsh ... show interfaces` 的 `Met`），修复 Metric 低于接口 Metric 时返回 `ERROR_BAD_ARGUMENTS(160)`、导致全部路由回退 `route add` 的问题；`route add` 兜底使用路由分量 1，两条路径的有效跃点一致；兜底日志附带 `CreateIpForwardEntry` 返回码
- Windows IPv4 属性窗口：IPHLPAPI 写入地址后补写网卡静态配置（`EnableDHCP=0`、`IPAddress`、`SubnetMask`），修复「详细信息」有地址但 TCP/IPv4 属性页 IP 与掩码为空的问题，与官方客户端 `netsh ... static` 行为一致
- Windows 连接性能：Win10/11 网卡地址配置改为 IPHLPAPI `GetUnicastIpAddressTable` / `CreateUnicastIpAddressEntry` 直接写入并回读，避免 `netsh`「返回成功但地址未生效」；仅 API 失败时回退 `netsh`，兜底按 20 秒总时长轮询（第 6 秒仍无地址时重试一次 `delete+add`），修复 v1.3.3 因 6 秒短窗口导致的「设置网卡地址失败（当前：无地址）」随机失败；资源路由改用 IPHLPAPI `CreateIpForwardEntry` / `GetIpForwardTable` / `DeleteIpForwardEntry`，NextHop 为虚拟网关 VIP-1，Metric 为接口 Metric + 1，移除批量 `cmd` / `New-NetRoute` 进程调用；API 失败时回退单条 `route add`；旁路路由一次 `route print` 同时读取活动路由与默认网关。Windows 7 配址保持原有 `netsh` 路径，资源路由同样优先 IPHLPAPI、失败回退 `route add`
- 异常退出补偿：会话标记额外记录 macOS utun 名称与 VIP；下次启动/连接前仅当接口地址与记录一致时关闭该 utun 并清理关联路由，避免误伤同名接口
- 网卡自检：注入测试路由前先检查同前缀路由冲突，发现被其他接口占用时直接给出冲突接口并跳过后续测试；macOS 接收方向改为由系统 `ping` 主动向测试目标发包、读循环读回该 ICMP 请求，直接验证真实路由与读路径；Windows / Linux 保持原有「注入报文并等待系统回包」验证方式
- macOS 数据面：utun 的对端地址与资源路由下一跳改为 **VIP-1**（与官方客户端 `inet VIP --> VIP-1` 一致），修复把本机 VIP 同时当作对端时 `route get` 回读通过、但系统流量不进入 utun 的问题，自检「接收方向」随之恢复；`HELPER_VERSION` 升至 `1.2.4`
- 登录、短信登录、改密与找回密码的账号/密码字段改为 Base64（对齐官方客户端 3.6.6.19）；无图形验证码时不再发送空 `Gid`，修复本地账号首次登录被网关误报 `-40081`、无法进入改密流程的问题
- 登录 User-Agent 保持无 `VERSION` 后缀；官方客户端的版本后缀未观察到参与登录校验，避免在 macOS/Linux 上声明为特定的 Windows 客户端版本
- 登录验证码策略按原客户端 `auth_param.gid`（`on`/`auto`/`off`）与 `login_check_verify` 解析；`auto` 模式在 `login_err_num >= 3` 后自动要求图形验证码，失败次数按账号跨连接保留
- `-40081` 附带密码状态文本时转入改密窗口：网关 `ErrMsg` 明确提到密码到期、首次登录、初始密码或管理员要求改密时，映射为对应返回码并弹出改密窗口；普通凭据错误仍保持原提示
- 凭据错误优先展示网关 `ErrMsg`，不再被固定的「账号或密码错误」掩盖
- 忘记密码重置成功后自动把新密码带回登录表单；切换账号时清除上一个账号自动填入的密码，避免用旧密码登录报 `-40081`
- 补齐登录改密提示（密码到期、过弱、首次登录、管理员要求改密）与「需要修改密码后才能登录」的中英文映射；新增文案同步检查规范
- 自动重连日志去掉「（等待 N 秒）」：该文案在每次重连尝试前打印，与实际重连耗时不一致
- 找回密码成功提示补充「新密码已自动填入」，与登录框自动回填行为一致
- 网卡自检：切换页面后保持运行与按钮旋转状态；每一步完成后立即展示；开始前清理上次残留的 `TopSAP` 虚拟网卡，修复 `Win32 1247` 与残留网卡；增加并发运行保护
- macOS：路由改为 `route -n add -net <dest> -netmask <mask> <VIP>` 并回读接口；DNS 通过 `networksetup` 按「VPN DNS 在前、原 DNS 在后」写入当前网络服务，断开时恢复原列表或自动获取；helper 增加 `networksetup` 白名单并独立版本号以触发重装
- Linux / macOS 自检：Unix TUN fd 改为非阻塞，读线程改为每轮 `poll` 后最多读取 32 个报文并用 `try_send` 投递；`reader.join()` 不再阻塞异步任务，自检结束能正常清理路由与网卡
- Linux 自检残留：开始前仅删除带自检地址 `10.99.99.2` 的 `topsap0`，避免误删正在使用的连接网卡；自检运行中拒绝连接，连接流程中或存在待清理资源时拒绝自检
- Linux TUN 错误提示：`EPERM/EACCES` 提示需要 root 并给出 `sudo <当前exe>` 命令；`EBUSY` 提示 `topsap0` 被占用并给出 `sudo ip link del topsap0`，不再混用同一条「特权 helper」提示
- Linux 未提权启动：普通用户双击启动时弹窗提示改用 `sudo /usr/bin/topsap-client`；Linux 自检与网卡配置文案移除「系统授权框 / helper」，macOS 保持原提示
- 记住密码：`keyring` 补齐 `apple-native`、`sync-secret-service` 与 `crypto-rust` 后端，修复 Linux / macOS 因退化为进程内 mock 导致「保存成功但重启读不到密码」的问题；CI 增加 `libdbus-1-dev` / `pkg-config`
- 记住密码说明统一为「系统安全存储」，避免在 Linux / macOS 上仍显示「系统凭据管理器」
- macOS 自检接收方向：注入的 ICMP 请求改为「测试网段地址 → 本机 VIP」，由系统生成回包并经测试路由回到 utun；修复 macOS 上因目标非本机、内核不回包导致的「接收方向失败」
- macOS DNS：原 DNS 为自动获取、`networksetup -getdnsservers` 为空时，读取 `scutil --dns` 的默认接口解析器（含 IPv6），仍为空则回退 `networksetup -getinfo` 的 `Router`，按「VPN DNS + 原 DNS」写入；helper 增加 `scutil --dns` 白名单并升级版本以触发重装
- macOS 路由：回读同时比对 `route -n get` 的 `destination` 与 `mask`，修复被 `/24` 覆盖的 `/32` 与 `/31` 被误判为已存在而跳过的问题；删除路由失败时再按 VIP 网关形式补删一次
- 英文映射补齐：macOS helper 未运行、网卡地址配置失败、Windows 虚拟网卡/会话创建失败（含 Win32 提示）、`设置网卡地址失败` 的尝试轮次、Linux/通用 TUN 创建失败、hosts 读写失败；自检明细未命中专用句式时回退到通用后端错误映射
- 网卡自检：去掉 45 秒全局超时，改为管理员、残留清理、建卡、配置地址、注入路由、ping、读线程回收与清理等每个步骤独立 60 秒超时；超时只标记当前步骤失败并继续清理，被取消的系统命令随 future 结束，避免残留 `netsh`/`route` 占用网卡
- macOS DNS：原 DNS 只追加 IPv4，忽略 `scutil --dns` 返回的链路本地 IPv6；断开时仍按原列表或 `Empty` 恢复
- macOS 路由：回读改用网段内主机地址并重试一次，以回读结果判定是否生效，修复路由实际已存在（`route add` 返回非零）时误报「未生效」的问题
- macOS 代理绕过：改为经 privileged helper 执行 `networksetup`，修复普通用户写入 `-setproxybypassdomains` 失败且仅记录日志的问题；helper 白名单新增 `-getproxybypassdomains` / `-setproxybypassdomains`，服务名与条目按既有规则校验，`HELPER_VERSION` 升至 `1.2.3`

## 1.1.0

### 新增

- 异常退出会话补偿：登录成功后加密记录网关、端口与 `session_id`；强杀、崩溃或断电后，下次启动/连接前自动补注销，降低 `Ret=-40077` 单点冲突
- 关机前限时断开：Windows `WM_ENDSESSION`、Linux/macOS `SIGTERM`/`SIGINT` 与 macOS `RunEvent::Exit` 最多等待 2 秒完成断开与注销，超时后交由系统回收 TUN 网卡与路由
- 连接建立失败后主动注销已登录会话，避免残留会话占用单点名额
- 已登录自动踢出：登录返回 `-40077` 时重新获取 `auth_param`，通过 `user_pswd_r`（`U/HASH/S_CODE`）踢出旧会话并继续登录；不依赖本地会话标记，覆盖官方客户端异常退出场景
- macOS 特权 helper：首次启动通过系统授权框安装 root LaunchDaemon（`com.topsap.next.helper`），GUI 保持用户身份；helper 创建 utun 并通过 `SCM_RIGHTS` 传回 fd，只执行 `ifconfig`/`route` 白名单命令，自检与建卡均通过 helper 完成

### 变更

- 断开流程中注销请求与路由清理改为并发执行，缩短异常网络下的断开耗时
- README、架构文档与诊断说明同步异常退出补偿边界、`-40077` 自动踢出与 macOS 提权行为

### 文档

## 0.1.0

首个版本：用 Tauri 2 + Rust 重写 TopSAP / NGVONE 客户端。

### 新增

- 登录：能力探测、图形验证码、账号密码登录、注销
- 动态验证码二次认证：密码校验返回 `-40039` 时自动发送并弹出短信 / 企业微信验证码输入，支持重新发送倒计时、3 次重试与 300 秒超时清理；重发使用 `U/P/Gid`，提交使用 `U/SMS/SMS_TIME`，修复 `-40135`
- 中英文切换：顶栏一键切换中文 / English，语言偏好本地保存并支持跟随系统；主要界面与弹窗均已翻译，后端 DNS/端口/网关返回码等错误按句式映射为英文
- 设置即时生效：设置窗口内主题、语言、通用开关与连接配置修改后立即保存，无需底部保存按钮
- 外观设置：主题与语言统一为下拉框，两者均支持「跟随系统」并作为默认值
- 主题切换动画：浅→深从右向左、深→浅从左向右平移展开；不支持 View Transitions 的 WebView 自动回退
- 自绘下拉框：展开时箭头旋转，菜单跟随深浅色主题，替代系统原生下拉菜单
- 浅色主题交互反馈：新增独立悬浮色与描边，侧栏、图标按钮、下拉选项在浅色背景下悬停清晰可见
- 多线路手动选路：新增 `probe_lines` 命令并发生成延迟列表，连接前弹窗选择线路
- 隧道：TLS 长连接、16 字节分帧、双向数据泵、异常断开自动重连
- 数据面：Wintun 虚拟网卡、IP 包收发、MTU 1400
- 网络配置：网卡地址（三轮重试 + 回读）、路由注入（批量 + 回读 + PowerShell 回退）、网卡 DNS
- 断开清理：清理账本逆序撤销；启动时残留检测与一键清理
- 网卡自检：管理员、DLL、建卡、配址、回读、测试路由、写路径、读路径、跨网段投递
- 界面：连接 / 诊断两页 + 独立设置窗口（左侧子菜单、右侧内容），深色与浅色主题，实时流量与日志
- 连接后信息面板：资源列表（分组/搜索/折叠，最大高度 420px 内部滚动）、基本信息、60 秒流量曲线、登录信息（本次/上次成功与失败记录）
- 信息卡片细节：默认网关星标实心高亮、基本信息/登录信息列距加大、流量图刻度与曲线分离；流量图增加面积填充与悬停时间/收发流量提示；连接配置校验与动态验证码错误统一改为 toast
- 隧道类型按原程序映射：0/1=透明访问、2=网络隔离、3=网络完全代理；登录信息地址只显示虚拟 IP；流量图改为每秒固定采样并修正悬浮坐标偏移
- 连接配置管理：多配置保存、编辑、删除、设为默认，支持导入 / 导出 / 清空；选中配置后隐藏网关地址与端口，支持自动选最快线路或连接前按延迟手动选路
- 多线路接入：单线路、多线路优选（并发探测选最快）、多线路备份（按顺序重试）
- 忘记密码：修正为 `/vone/find_pswd` 两步流程；第一步 `Gid/S_Gid` 使用同一图形验证码，网关要求二次验证时继续输入动态验证码并提交明文新密码
- 修改密码：连接成功后可修改当前账号密码，走 `/vone/chg_pwd`；Cookie 的 `sv_un` 为明文账号并补齐 `seccheck=0` 与会话 ID，登录态请求体只发明文 `P1/P2`
- 交互细节：记住密码卡片整块可点击切换；虚拟 IP 显示补充冒号；关于页移除安全提示卡片；顶栏移除重复的连接状态胶囊；清空/删除连接使用项目风格确认弹窗；新增连接按钮移至列表底部
- 中英文覆盖：侧栏折叠/展开、主题切换、语言切换、弹窗关闭等悬浮提示与无障碍标签全部随语言切换
- 界面增强：侧栏可折叠、顶栏主题切换图标、操作提示统一为顶部 toast、所有可交互元素统一手型光标
- 连接页布局：状态卡片不再重复展示错误正文，错误统一由顶部 toast 呈现；连接与断开按钮合并到登录卡片底部、统一宽度并移除按钮箭头；浅色主题主按钮改为更浅的渐变；移除密码为空与过短时的红色提示
- 错误提示归一：DNS、TCP、HTTP 状态与 TLS 握手错误转为可操作的中文说明（未知主机、连接被拒绝、端口未提供 HTTPS 服务等），不再展示系统本地化原文与 HTML 响应片段
- 连接体验修正：重启后自动选中默认配置；资源仅在配置了 `http/https/smb` URL 时可点击并调用系统浏览器打开；短信重发补齐 `U/P/Gid`、提交补齐 `SMS_TIME` 并使用网关 `sms_time`；动态验证码错误 `-40135` 与改密原密码错误 `-40078` 均有明确提示；不再写入系统 hosts（与原客户端一致），仅保留旧版本残留清理
- 密码流程二次修正：改密登录态请求体只发 `P1/P2` 并补齐 `sv_un`/`seccheck`/会话 ID；短信重发与登录的 `SMS_TIME` 改取 `topsecsveee` Cookie，并保留网关下发的 `login_err_num`；`-40226` 直接展示网关 `ErrMsg` 中的动态密码策略并兼容 URL/`%u` 编码；忘记密码改为邮箱文案；新密码校验以后台动态策略为准，不再做前端固定规则判断；无 URL 的资源项保留悬浮反馈但不可点击
- 密码状态与会话修正：登录返回 `-40022/-40023/-40024/-40199` 时弹出无会话改密窗口，成功后自动用新密码重试；忘记密码重置成功后记录短期标记，登录前尝试刷新网关密码有效期，规避原网关重置后仍报到期的缺陷；连接成功后按 `pwd_remind/account_end` 提示密码与账号剩余天数；已连接改密成功后按原客户端注销会话并清除本地记住的旧密码
- 系统集成：托盘菜单、单实例、关闭到托盘、退出前断开
- Windows 便携目录：配置写入 `<exe>\config`，日志写入 `<exe>\data\logs`，WebView2 数据写入 `<exe>\webview`，不再使用 `%APPDATA%` / `%LOCALAPPDATA%`
- 凭据：系统钥匙串优先，回退机器绑定 AES-256-GCM
- 日志：界面实时推送 + 本地文件轮转（2 MB）

- 代理绕过：设置窗口新增「代理绕过」子菜单，默认维护 `*.sunline.cn` 与 `*.sunline-i.com`，支持自定义域名/泛域名/IP；Windows 写 `ProxyOverride`，macOS 写 `networksetup` 逐网络服务列表，Linux 写 GNOME `gsettings ignore-hosts`；规则/全局系统代理模式下这些地址不走代理；仅对使用系统代理的程序生效，TUN/透明代理无法覆盖

### 修复

- 找回密码：第一步 `-40075`/「禁止找回密码」统一提示「该用户不存在或已被禁用」；第二步 `-40052/-40071`/「找回密码失败」提示「新密码不能与旧密码一致」
- 改密提示：密码修改成功类 toast 固定使用绿色样式，避免浅色/深色主题下被渲染成错误色
- 密码输入框：隐藏 WebView2 原生眼睛，右侧固定显示/隐藏按钮，覆盖登录、忘记密码、到期改密与已连接改密
- 改密重登：改密成功后新密码自动填入登录框，重新登录成功的 toast 末尾提示「登录密码已自动填入」
- 无资源连接：连接成功后资源列表为空或没有可下发地址时提示原因并自动断开
- 路由下发：按原客户端 `na_client.exe` 行为改为 ACL 目标网段与资源 `ip/mask` 并集；修正本网关把 IPv4 目标写在 `d_ip_v6` 导致 ACL 路由全部被跳过的问题，隐藏资源也参与路由
- 找回密码验证码：第一步除验证码错误外的失败自动刷新图形验证码
- 找回密码成功：第二步 `-40230` 按成功处理，绿色提示并自动关闭弹窗
- Toast 风格：使用 Sonner `richColors` 原生样式（成功浅绿、错误浅红、警告浅黄），不再用自定义描边/半透明背景覆盖
- 图形验证码登录：选路探测的 Cookie 继续用于验证码与登录，修复 `auth_param`/`cgid`/`topsecsvkkk` 丢失导致的 `-40135`；验证码错误时自动刷新并最多重试 3 轮
- 动态验证码登录：按官方客户端日志改为 `POST /vone/login/user_pswd`，表单 `U/SMS/SMS_TIME=0/HASH/S_CODE`，复用密码请求的 `HASH/S_CODE` 与 `-40039` 挑战 Cookie，修复特殊用户输入正确验证码仍报 `-40135`
- 新旧密码相同：前端预检并映射 `-40037`/`-40129` 为「新密码不能与旧密码一致」，覆盖已连接改密与登录时到期/首登改密
- 无资源提示：登录返回 `-40123` 与连接后无可下发地址统一提示「用户未拥有任何资源地址，请联系管理员」

### 兼容性

- 支持 Windows 7 SP1 / Windows 10 / Windows 11（x64）
- 支持 Windows 11 / 10 ARM64：使用 `wintun-arm64.dll`，安装包与便携包按架构选择驱动
- Windows 7 通过 `RtlGetVersion` 运行时检测（版本 6.1），自动切换到 `netsh` 兼容路径，不依赖 PowerShell 3.0+ 的 NetTCPIP 模块；Windows 10/11 保持原有配置逻辑
- Windows 7 需预装 WebView2 Runtime 109 与 Visual C++ 2015-2022 Redistributable
- 支持 macOS（Intel / Apple 芯片）与 Linux（amd64 / arm64）：使用系统 TUN 设备（`tun` crate），通过 `ip` / `route` / `ifconfig` 配置地址与路由，需要 root 或 `sudo`
- macOS 应用未签名与公证，首次打开需移除 Gatekeeper 隔离属性

### 已知限制

- 仅支持 `ngvone` / `cipher_type=0` 网关
- macOS / Linux 数据面已实现并纳入 CI 构建，尚未完成真机连接回归
- Unix 不修改全局 DNS：`set_dns` 返回 false，内网域名仅解析保留
